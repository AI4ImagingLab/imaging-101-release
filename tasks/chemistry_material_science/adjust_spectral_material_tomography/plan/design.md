# Shipped interfaces and execution flow

## Scope and numerical ownership

This task implements a reference-release variant of ADJUST for the complete measured 600-view spectral CT scan. The local code owns the acquisition matrix, Beer-Lambert correction, SIRT self-calibration, constrained factor updates, line search, and stopping rules. SciPy supplies sparse storage and basic matrix operations; CuPy compiles the explicit general ordered CSR kernel and owns GPU buffers. PyTorch modes are retained as historical diagnostics. Neither runtime imports ASTRA, ADJUST, MinConf, or another task.

The selected published four-material experiment uses the release's row-equality variant, with the documented removal of its total-sum guard in the dictionary-weight feasibility routine. The routine is alternating feasibility projection and is not an exact Euclidean projection. See approach.md for the equations and validation.md for the source discrepancy and independent QP evidence. These distinctions are part of the current implementation, not optional alternate modes.

## Array conventions

Let V=600 views, B=128 acquired energy bins, D=257 detectors, P=255*255 pixels, M=4 latent materials, K=4 augmented dictionary atoms, and C=65 selected bins. Internal observations have shape (V*D,B), with ray index view+V*detector. Pixel index is row+255*column. Image rows run from positive to negative vertical coordinate; columns run from negative to positive horizontal coordinate. A map column is reshaped with order='F'.

Public arrays have a leading batch dimension of one. Photon arrays are uint16; geometry, energy, and dictionary arrays are float64. All saved submission arrays are float64. Projection weights and SIRT arithmetic are float32 to reproduce the selected CPU line and SIRT discretization. ADJUST and all its dense factors use float64. The CPU and CUDA implementations preserve these dtypes rather than silently changing precision.

Counts and dark/flat fields are in detector counts. Corrected data, spectra, and pixel-line projection weights are dimensionless. Maps represent dimensionless basis abundances; they have not been independently calibrated as absolute mass density. The supplied dictionary is in cm^2/g before the explicit nominal .015 g/cm^2 scale. Angles are radians, energy is keV, and physical geometry constants are mm.

## src/preprocessing.py

`load_observations(path='data/raw_data.npz') -> dict[str, ndarray]` opens the NPZ with allow_pickle=False and validates six required keys, exact batch-first shapes, numeric finite contents, and strictly positive dark-corrected transmission and flat fields. It removes the batch axis by copying each array. The returned keys are counts (600,128,257), dark and flat (128,257), dictionary (3,128), angles (600,), and energies (128,). It raises ValueError for a malformed shape, missing key, nonnumeric/nonfinite input, or nonpositive corrected count. File-system and NPZ errors propagate to the caller. No calibration is estimated here.

`correct_counts(counts, dark, flat) -> ndarray` evaluates log((flat-dark)/(counts-dark)) after converting photon counts to float64. This avoids unsigned subtraction wraparound. It rejects nonpositive ratios, reverses the acquisition view axis as in the release, transposes detector/view/bin, and returns a float64 (154200,128) array. It does not clip counts, smooth spectra, crop detectors, or remove views.

`calibrated_dictionary(dictionary, reconstructed_channels) -> (dictionary65, quartz128)` accepts the raw (3,128) float64 dictionary and the freshly computed (65025,128) SIRT channel images. Each channel is reshaped in column-major order. The mean over Python rows/columns 129:140 is computed in float32, giving a (128,) quartz estimate from the same observations. The routine stacks .015*dictionary and quartz, then selects Python columns 29:94. It returns (4,65) and (128,). This quartz curve is an intermediate reconstruction, not public instrument calibration or actual truth.

## src/physics_model.py

Constants encode the source-release fan geometry: source-object distance 57.999001 mm, source-detector distance 883.081116 mm, detector pitch .80 mm, reconstruction size 255, detector count 257, and the release's detector-center offset. All source/settings differences are preserved in validation.md rather than silently averaged.

`geometry_vectors(angles) -> ndarray` converts a one-dimensional angle array to float64 (nangle,6) source location, detector-center location, and detector-step components in image-pixel units. It applies the measured center shift in the detector direction. The inclusive 0..2*pi acquisition grid is supplied by the visible array rather than regenerated by the runtime.

`build_system_matrix(vectors, size=255, detector_count=257) -> scipy.sparse.csr_matrix` accepts those six-component fan vectors. It explicitly computes float32 line lengths through constant-valued square pixels. Detector basis rounding precedes detector-start computation, and repeated float32 coordinate addition preserves the compiled oracle convention. Returned shape is (nangle*detector_count,size*size), with angle-fast rows and column-major pixel columns. The full matrix has 46,901,466 stored weights. Building it allocates sparse coordinate buffers before CSR conversion; the task must be run with adequate RAM. It performs no disk caching and does not consult a hidden operator asset.

`forward(matrix, image)` and `adjoint(matrix, measurements)` are direct matrix multiplication and exact transpose multiplication. Input leading dimensions must match the matrix domain or range; normal NumPy/SciPy shape errors propagate. They do not guess image orientation or reshape batch-first submissions.

`preserve_source_pixel_order(matrix, size, vertical_rays)` mutates the freshly constructed CSR's within-row index/value order and returns it. `vertical_rays` is a Boolean array `(nrays,)` derived from the actual float32 source/detector direction. Vertical rays traverse rows before columns; horizontal rays traverse columns before rows. This recovers the original compiled kernel's dominant-axis accumulation convention despite the column-major pixel labels. Weights, column labels, and the mathematical linear map are unchanged. CSR is intentionally marked unsorted; callers must not canonical-sort it merely as a storage optimization. An independent original fixture checks exact index, pointer, and value sequences.

`sirt(matrix, data, iterations=100, backend='cpu', verbose=False) -> ndarray` accepts (nrays,npixels) sparse weights and (nrays,nchannels) corrected observations. Both cpu and cuda_ordered dispatch to `source_ordered_sirt(matrix, data, iterations=100, verbose=False, backend='cpu')`; other CUDA variants retain different diagnostic arithmetic. The selected function converts weights to float32 without sorting. For the bound (154200,65025) geometry it reorders rays into detector-fast native acquisition order and relabels pixel columns to row-major; smaller mathematical cases retain caller order. It computes source-ordered row/column sums, sets reciprocal zero where absolute sum<=1e-6, and builds CSR [I,-W] with each identity element preceding its ray entries. A multiplication by [Y;X] therefore starts each residual at Y and subtracts every pixel contribution sequentially. The transposed CSR accumulates native rays, then column scaling is applied before adding the correction. X starts at zero; relaxation is one; no positivity projection or early stopping occurs. Output is float32 (npixels,nchannels), restored to MATLAB pixel order for the bound geometry. The selected cuda_ordered path uses OrderedCsr for precisely these augmented forward and transpose products, retaining CPU float32 normalization, pointwise updates and quartz averaging. After both device CSR copies are complete, the current CUDA stream is synchronized and their unused CPU CSR references are deleted, ensuring queued copies no longer depend on host buffers. Both operator objects are closed in a finally block. It computes all128channels100iterations freshly; no archived quartz curve or approximate residual is used.

## src/linear_algebra.py and src/blas_worker.py

`SourceBlas(timeout=120.)` is an explicit context manager for the separately validated generic Linux OpenBLAS0.3.26 backend. It starts a persistent Python standard-library worker using source-relative paths; Windows resolves that path with WSL wslpath, selects optional IMAGING_WSL_DISTRO, and starts python3. IMAGING_BLAS_LIBRARY_PATH optionally supplies the generic library search directory, and IMAGING_BLAS_LIBRARY optionally selects its soname. No task-private/upstream path is embedded. Native Linux uses the current Python executable. The worker loads cblas_dgemm, cblas_ddot and cblas_dsyrk via ctypes, selects four threads and reports its full configuration/byte order. An unexpected configuration fails startup. No imaging method, observations, saved result or target is loaded by the worker.

`SourceBlas.matmul(left,right)` accepts compatible2Dfloat64 arrays. Inner dimension below4096 uses local NumPy with F-contiguous output; longer contractions use generic DGEMM. This dimension-only split avoids transferring large short-inner outputs and is independently validated on the real original spectral objective. `SourceBlas.dot(left,right)` accepts equally shaped arrays, serializes F-order vectors and uses DDOT for distinct operands; same-object self products use DSYRK, preserving Octave's actual s-transpose-s role. Both return fresh arrays/scalars. Binary messages consist of four little-endian uint64 operation/dimension fields and raw float64 operands; no pickle is used. Responses carry an explicit length. A single-worker executor enforces request timeout and reports worker failures. `close()`/context exit stop the owned worker, close streams and restore the previous context; nested contexts are rejected.

`SourceBlas.power(base, exponent)` accepts two real scalar values, transmits two float64 operands with operation5 and returns a Python float containing the selected Linux libm power result. The worker delegates only this general arithmetic primitive to its standard-library `math.pow`; it receives no objective, model or reconstruction state. `solvers._scalar_power(base, exponent)` selects this method inside the numerical context and the host `math.pow` otherwise. Spectral, spatial and joint-comparison least-squares objectives call it for the norm-squared numerator while retaining the original multiply/divide order. Its exact platform rounding is validated against independently executed original Octave powers, including actual measured-data residual norms and independent numerical boundaries. Host-native calls outside the validated context have no cross-platform last-bit guarantee.

`_cubic_step` also calls the helper for the original explicit d1^2 in its discriminant; other source multiplications retain their original roles. All384 actual original cubic inputs/outputs are checked in an actual SourceBlas context, rather than assuming the host fallback is identical on every future scalar.

`current_backend()` returns the current numerical context or None. Solver `_matmul` and `_dot` consult it; outside the context they retain the selected NumPy/Torch behavior. `_matmul` never sends Torch arrays implicitly to Linux. Fixed original SPG objectives/gradients/trials/final weights all match bitwise through the shipped context. Standard entry uses this context; complete-path validation remains pending. Importing either module starts no process.

## src/deterministic_sparse.py

`OrderedCsr(matrix)` accepts a SciPy CSR-compatible float32 or float64 matrix and owns device copies of its unchanged row pointers, column indices and coefficients. Dimensions and nonzero count must fit int32. CuPy 13.6.0 supplies NVRTC compilation and device buffers only; the complete generic scalar reduction is visible in the module. One CUDA thread owns one output element, walks CSR entries sequentially and uses explicitly rounded multiply/add, with contraction disabled. It performs no acquisition construction, optimization, projection or imaging-library call.

`multiply(values)` requires a matching-dtype two-dimensional host array whose first dimension is the matrix column count. It copies C-contiguous operands to the device, computes the product and returns an F-contiguous host array `(matrix_rows, values_columns)` in the original dtype. Empty-column cases return an empty array. Invalid dtypes/shapes, oversized dimensions and use after close raise descriptive exceptions. Each operator has its own CuPy memory pool; `close()` releases its arrays and cached blocks, and destruction attempts the same cleanup. Importing this module starts no GPU computation. Small unsorted, cancellation-sensitive float32/float64 forward/transpose cases and repeated calls match independent SciPy arrays bitwise; actual benchmark trajectory validation remains a separate mandatory gate.

`LinearMap(..., backend='cuda_ordered')` owns one OrderedCsr for W and one for its transpose, with F-order host factors/outputs. This selected deterministic acceleration passed actual-checkpoint primitive checks and complete independently executed CPU100 versus cleaned orderedGPU100 parity: every captured map/weight checkpoint is bitwise equal. The installed historical PyTorch/cuSPARSE operation was independently measured as nondeterministic; it is not the selected benchmark backend.

## src/solvers.py: computation and constraints

`cast_sparse_preserving_order(matrix,dtype)` returns a new CSR with cast data and unchanged copied indices/pointers. Ordinary SciPy astype can sort an unsorted CSR during a precision change, so both ADJUST and cJoint call this helper before LinearMap. The actual multiply boundary is regression-tested against the independent original index sequences. LinearMap accepts cpu, cpu_sparse, cuda, cuda_sparse and cuda_ordered; the sparse-only CUDA mode keeps dense factor arithmetic on the host.

`frobenius_norm(value)` returns a Python float using explicit serial scaled accumulation in F-vector order. It accepts a real NumPy array or tensor; tensors are transferred to host before this scalar reduction. NumPy maximum-accumulate identifies scale changes and cumsum preserves each fixed-scale interval's addition order. `_norm` delegates to it. `_dot(left,right)` evaluates the BLAS inner product of F-flattened host arrays; `_sum(value)` performs a sequential F-flattened sum. These are distinct source call roles rather than interchangeable reductions. There are no archived numeric constants in the runtime.

`LinearMap` additionally accepts `backend='cpu_sparse'` for independent deterministic-CPU source pairing. It keeps the original CSR traversal, materializes each dense operand in C order for SciPy multiplication, and returns F-contiguous host output, matching the original relay's serialized return. `array` and `zeros` use F order as well. This separates original dense-memory conventions from the nondeterministic CUDA sparse primitive, without changing W, its transpose, or any inverse update. The independently executed original CPU relay imports no cleaned code. The complete100-step independent source/ordered-GPU gate passed; full1000-step validation remains mandatory.

`LinearMap` additionally accepts `backend='cuda_sparse'`. Sparse matrices use the same explicit CUDA CSR storage as `cuda`; `array` and `zeros` return F-contiguous NumPy arrays. `_host_sparse_product` transfers a C-contiguous dense input to CUDA, applies the selected sparse matrix, and copies the result to an F-contiguous host array. `multiply` and `transpose` use this boundary; `numpy` returns a host view. Dense products and factor updates therefore remain on the CPU, matching the original oracle's actual execution roles. This historical diagnostic mode is not the standard default: independently repeated identical CSR calls are nondeterministic and sensitive full trajectories failed strict parity.

`LinearMap(matrix, backend='cpu')` owns sparse forward and transpose arithmetic. backend must be cpu, cpu_sparse, cuda, cuda_sparse or cuda_ordered. CPU retains SciPy CSR; CUDA explicitly transfers CSR arrays and their transpose into torch sparse tensors. CUDA availability and memory errors propagate. Its `array(value)`, `zeros(shape)`, `multiply(value)`, `transpose(value)`, and `numpy(value)` methods convert numeric arrays, allocate backend arrays, compute Wv/W'v, and return host arrays. The matrix dtype determines dense dtype. `numpy` does not promise a private copy; callers that retain a best iterate copy it explicitly.

`initial_state(pixels, materials, atoms, seed=10) -> (maps, weights)` uses the MT stream matching the independent Octave rng(10,'twister') case, fills arrays in column-major order, and normalizes every map row to sum one. It returns float64 shapes (pixels,materials) and (materials,atoms). It does not reseed global NumPy state.

`project_simplex_columns(values, mass=1.0, equality=False)` implements sort-and-threshold projection per column onto nonnegative column sums <=mass or =mass. `project_material_maps(values)` applies the inequality projection to each pixel row. Both CPU and CUDA map projections implement the same rule. `project_dictionary_weights(values)` alternates row equality and column inequality projections, at most 10000 passes, stopping when their difference has norm <1e-6. It removes the source's erroneous sum>=1 guard. CUDA factors temporarily move to host for this small (4,4) operation and return with their original device/dtype. None of these functions mutates the caller's trial array.

`spectral_objective(weights, data, projected_maps, dictionary, norm_data)` returns the scalar .5*||projected_maps*weights*dictionary-data||_F^2/norm_data and an (M,K) gradient. `spatial_objective(maps, spectra, data, operator, norm_data)` returns the same objective with explicit W and its exact transpose gradient (P,M). norm_data is ||original_data||_F, not its square and not the lifted-data norm. All dense products preserve backend precision. Functions accept backend arrays; their task-specific objective and gradient are local executable mathematics.

`spectral_projected_gradient(objective, values, projection, max_evaluations=2, memory=2, progress_tolerance=1e-12, sufficient_decrease=1e-12)` returns an updated factor array. It evaluates the supplied gradient, BB1 scaling, the source-compatible first step, projected curvilinear trials, a nonmonotone window, two-point cubic backtracking, and progress tests. The source's <= evaluation-loop convention permits an initial evaluation plus trials beyond the nominal counter. `_cubic_step` is an internal numerical helper. The routine returns no optimizer object and relies on no ready-made imaging optimizer.

## src/solvers.py: reconstruction and comparisons

`adjust(data, matrix, dictionary, materials=4, iterations=1000, inner_evaluations=2, rho=.01, seed=10, backend='cpu', verbose=True) -> dict` runs the implemented joint inference on float64 data (154200,65) and dictionary (4,65). Each outer iteration updates weights, computes spectra, updates maps, adds the residual to the lifting accumulator, records convergence/feasibility, chooses a coherent best map/spectrum/weight triple, tests stopping, and adapts rho. It returns maps (65025,4), spectra (4,65), weights (4,4), history (n,4), feasibility_history (n,5), and runtime_seconds. history columns are relative data residual, residual change, summed factor change, and rho used. Feasibility columns are map negativity, map row-sum excess, weight negativity, weight row-equality error, and weight column-sum excess. The arrays correspond to the best relative-residual iterate; histories describe every executed outer iteration. Zero/nonfinite observation norm raises ValueError. With verbose=True it prints initial and every 25th iteration. It writes no files.

`classical_joint(data, matrix, materials=4, iterations=500, seed=10, backend='cpu', verbose=True)` implements the reference cJoint comparison with nonnegative unrestricted spectra, box-constrained maps, unnormalized random initialization, three inner evaluations, fixed rho=.01, and source progress/Armijo tolerances 1e-9. It returns maps, spectra, history, and runtime_seconds; no dictionary weights are inferred. The notebook keeps this method separate from ADJUST and compares it to its independently executed source result.

`nonnegative_least_squares_small(gram, right)` enumerates the 15 nonempty supports for four latent components and solves each restricted normal equation, selecting the feasible minimum quadratic value. `factor_nonnegative(data, materials=4, replicates=10, multiplicative_iterations=100, als_iterations=30, seed=10)` uses ten random multiplicative starts followed by exact support-enumerated alternating NNLS. It returns nonnegative left/right factors. This is a mathematical port for RU/UR comparisons; it is not a claim of numerical equivalence to proprietary MATLAB nnmf.

`tikhonov_cg(data, matrix, iterations=20, tolerance=1e-6, regularization=.001, backend='cpu')` explicitly applies W'W+.001I and ordinary conjugate gradients to each right-hand side from zero. It returns host float64 (npixels,nrhs). `sequential_comparison(data, matrix, order='RU', backend='cpu')` performs reconstruct-then-unmix (20 CG iterations) or unmix-then-reconstruct (100 CG iterations) on all selected channels and the full image. It returns maps, spectra, relative_residual, and runtime_seconds. These comparison paths are called actively by the notebook; they are not part of the submission CLI.

## src/main.py: standard entry point

`run_pipeline(data_path='data/raw_data.npz', output_path='output/reconstruction.npz', backend='cuda_ordered', verbose=True, review_assets_path=None) -> dict` is the standard complete benchmark path, currently awaiting complete validation. The exact caller/data flow is:

1. load_observations reads only the visible NPZ; correct_counts derives all 128 transmission sinograms.
2. geometry_vectors and build_system_matrix construct W from visible angles and documented acquisition constants.
3. sirt performs all 128 channel reconstructions for 100 source-ordered updates. The selected cuda_ordered inverse backend selects its exact ordered-GPU calibration path; diagnostic inverse modes retain the source-ordered CPU calibration path.
4. calibrated_dictionary computes the quartz self-calibration and selects all 65 retained bins.
5. SourceBlas starts the validated generic math worker, adjust executes the full 1000-outer-iteration path unless source stopping tests fire, and context exit closes that owned worker. The default sparse products are CUDA with C-input/F-host-return; factors remain on the host.
6. Each best map column is reshaped (255,255) with order='F'; the arrays receive a batch axis. The output parent is created and np.savez_compressed writes reconstruction (1,4,255,255), spectra (1,4,65), and dictionary_weights (1,4,4). If output_path is None no file is written.

The returned dictionary also contains result, matrix, observations, corrected_data, spectral_channels, quartz, dictionary, sirt_seconds, and runtime_seconds so the review notebook can inspect genuinely fresh intermediates without rerunning or importing an oracle. The dictionary is an in-memory maintainer interface, not another submission file.

If review_assets_path is provided, the function additionally writes exactly the fresh spectral_channels, quartz, dictionary, history, feasibility_history, solver_runtime_seconds, sirt_seconds and runtime_seconds arrays to that requested NPZ. The optional artifact is consumed by the active notebook, avoiding a second full reconstruction only to inspect intermediates; it is not solver input or part of the submission contract. Relative paths follow the caller's working directory.

`main(argv=None)` accepts --data, --output, --backend {cpu,cpu_sparse,cuda,cuda_sparse,cuda_ordered}, and optional --review-assets. It prints measured total runtime/iteration count and returns zero after successful output. `python -m src.main` calls it. The default uses explicit ordered scalar CUDA sparse products and the general Linux dense backend. CPU execution is available but complete CPU inverse parity is not claimed. Importing main has no Matplotlib backend side effect and does not launch reconstruction.

## Standalone evaluation boundary

`project_maps(images, angles)` independently integrates float64 material maps `(materials,255,255)` along all 257 detector rays of the supplied radian angles and returns `(views,257,materials)` in optical-depth map units. It constructs no full sparse matrix. `matched_line_integrals(images, source, detector)` evaluates the selected float32 line weights ray by ray, preserving repeated coordinate rounding. `ray_integrals` is a separate double-precision Siddon helper used for analytic geometry checks, not the acceptance operator: its exact-double intersections differ from the selected source discretization on rough pixel maps. Neither helper imports a reference-solver module.

`observation_consistency(prediction)` reads only public `data/raw_data.npz`, computes dark/flat corrected optical depths for reconstruction indices `0,50,...,550` (acquisition indices `599-view`), and compares all 257 detectors and 65 retained bins with projected maps times spectra. It returns a finite relative Frobenius residual. The required `forward_relative_l2_boundary` is an upper bound fixed as 1.1 times the independently validated source residual on these rays; final measurements are recorded in validation.md. Input/ref errors remain evaluator errors rather than silently omitting this criterion.

evaluation/judge.py imports no solver modules. `load_arrays` validates exact keys, shapes, float64 dtype, and finite values; `component_order` computes the single spectral assignment; `score_arrays` calculates per-component NCC/NRMSE for all three required quantities plus physical feasibility; `thresholds_from_config` validates metric directions/boundaries. `evaluate(prediction_path, asset_dir=None)` resolves the default hidden directory from its own source path and returns the independent report and exit status. `main(argv=None)` accepts --prediction and --report, creates the report parent, and writes UTF-8 JSON with status, passed, metrics, thresholds, and errors.

Actual truth takes precedence if provided; this measured scan has no actual truth, so the intended hidden asset is the independently validated corrected-reference result, baseline_reference.npz. The Judge never imports a solver, runs a submission, crops a prediction, rescales a map, or substitutes a cached output. Missing/malformed predictions and hidden-asset failures yield status=error/exit2; valid poor predictions yield fail/exit1; passing predictions yield pass/exit0. Report-write failure is an evaluator error printed to stderr. Thresholds must be finalized from independent full runs rather than self-comparison.
