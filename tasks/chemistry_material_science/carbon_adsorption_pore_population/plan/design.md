# Shipped interfaces and data flow

The task runs independently with NumPy,SciPy and Matplotlib. Original JSON parsing, thermodynamic pressure conversion and domain-library verification occur only in private captures. Runtime observations/calibration are NPZ. No generator is included because this is an existing real author isotherm. No private checkout or cross-task module is imported.

`preprocessing.load_observations(path)` loads allow_pickle=False and removes only the known leading batch axis, returning a dictionary of float64arrays:relative_pressure(96),loading(96),kernel_relative_pressure(177),kernel_loading(177,77),pore_width(77). Their units/order are fully documented in README. `calibration_with_origin(pressure,kernel)` returns178pressure coordinates and178x77responses by prepending the known zero boundary. `width_steps(widths)` returns firstwidth then successive differences, used for both raw and reported axes.

`physics_model.build_kernel(relative_pressure,kernel_pressure,kernel_loading)` validates interpolation bounds and returns shape(77,96), evaluated by positive shape-preserving PCHIP with no extrapolation. `forward(weights,kernel)` takes77dimensionless coefficients and sums each known pore's mmol/g response, returning96predicted observations. `objective(weights,kernel,loading)` returns the full squared-uptake sum; `objective_gradient(...)` returns the explicit77-vector analytic gradient. The standard optimizer uses the qualified source analytic gradient with observed mean-square scalar normalization; the same gradient also supports independent tests.

`solvers.spline_matrix(count=77,degree=2,n=100)` explicitly evaluates the clamped Cox–deBoor basis. It returns(100,77) for the standard and identity(count) for degree0. `reconstruct(raw,degree=2,initial=None)` forms the complete physicalmatrix, initializes all77weights tozero unless the notebook supplies a different public-data start, and runs the declared nonnegative SLSQP objective. It returns reconstruction(100),bin_weights(77),cumulative_weights(100),width_axis(100),unsmoothed_density(77),kernel(77,96),fitted_loading(96),objective(float),iterations(int),smoothing_matrix(100,77),convergence_certificate(dict with projected_kkt and relative_primal_dual_gap). Comparisons with otherdegree values change reporting-array lengths oraxes only; every solve still uses all96 observations.

`main.run(data_path=None,output_path=None)` resolves defaults relative to the task directory, reads the public NPZ, calls default reconstruct, creates the outputparent, and saves exactly reconstruction(1,100),bin_weights(1,77),cumulative_weights(1,100), float64. It also returns the diagnosticdictionary with actual runtime_seconds. `python -m src.main` prints objective/iterations. Importing any librarymodule changes no Matplotlibbackend.

`visualization.metrics(estimate,reference)` returns uncenteredNCC and dynamicrangeNRMSE. `normalized_density(axis,density)` returns a unit-area profile only for clearly labeled cross-method shape comparison and rejects zero area. It is not used for standard output, fitting or Judgealignment.

## Precision and certified convergence revision

An independent parent review found the prior raw-objective finite-difference SLSQP could return success=True at the unchanged Uniform0.01 initial coefficients, objective about3182 rather than20.97. That failed start and the superseded task/notebook are preserved privately; they are not convergence evidence. Adding analytic gradient alone still exhibited the same source SLSQP false termination. Scaling by the full kernel Lipschitz constant avoided the gross stall but left insufficient parameter convergence, and that trial is preserved as failed as well.

The newly qualified source variant divides the unchanged sum-of-squares objective and its analytic gradient by mean(observed_loading**2). This positive observed-data scalar changes no minimizer, kernel, nonnegativity, weighting across points or physical residual objective. SLSQP uses ftol1e-15,maxiter5000; all77bounds and the source identity inequality remain. Three independently initialized full96point runs in the isolated actual author-source copy reach physical objective20.970090134873 and all three required output arrays agree within the unchanged benchmark tolerances. Their fixtures/quality criteria are frozen BEFORE the cleaned optimizer change.

solvers.convergence_certificate(weights,kernel,loading) explicitly computes g=2K(K^Tx-y), L=2||K||_2^2 and projected residual ||x-max(0,x-g/L)||_infinity. It separately constructs a feasible NNLS dual v=r+delta*1 from r=K^Tx-y, delta=max(0,max_j[-(Kr)_j/sum_i K_ji])+1e-15, giving Kv>=0. Primal S=||r||² and feasible dual Q=-||v||²-2y^Tv yield relative gap(S-Q)/max(1,S). Return keys projected_kkt and relative_primal_dual_gap are dimensionless coefficient/relative objective diagnostics, not physical uncertainty.

reconstruct retains its public signature and all previous return keys, adds convergence_certificate, and reports the unscaled physical objective. It raises if optimizer status fails OR projected residual>1e-11 OR absolute relative dual gap>1e-6, preventing success-flag-only acceptance. Full multi-start and an injected false-success result are meaningfully tested. Native cases have projected residual7.53e-14/8.62e-15/3.37e-13 and feasible-dual relative bounds5.96e-9/9.44e-10/3.78e-8; coefficient dynamic-rangeNRMSE spread<=4.02e-7. The same source spline, normalization and cumulative convention remain untouched. This is an explicitly precision-refined corrected-source variant, not unchanged original defaults. Benchmark metrics/boundaries are unchanged.
