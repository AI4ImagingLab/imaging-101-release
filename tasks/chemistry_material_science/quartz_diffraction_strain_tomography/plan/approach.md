# Implemented forward model and corrected standard method

Use the author's existing simulated observations verbatim, without selecting rays, downsampling fields, or generating noise. All 500 by 192 observations and six tensor components are retained. The unknown is the symmetric strain field with component order xx,yy,zz,xy,xz,yz, dimensionless; x,y,z are reciprocal-vector tensor coordinates. Pixel row/column geometry follows the explicit positive-row Joseph convention in the README. Known support is an input morphology prior, not a hidden strain-derived calibration.

Let B be a Gaussian radial-basis renderer with 64 centers on an 8 by 8 regular grid in normalized row/column coordinates [-1,1], plus one constant bias. For normalized pixel coordinates z and center c, its supported basis value is exp(-norm(z-c)^2/(4*s^2)) with s=.16. Values below exp(-.5*(5/(2*s))) are set to zero, preserving the source's actual cutoff rather than relabeling it as a standard five-sigma radius. Every column is multiplied by the known support. B has shape (10176,65), float64 CSR. Each of six channels is rendered separately by CSR-vector multiplication to preserve arithmetic order.

P is the float32 Joseph ray integral divided by the float32 projection of the known support. It uses the original CUDA dominant-axis templates and native 3D texture interpolation, fractional interpolation precision 1/256, and sums 32 slices before multiplying the path step sqrt(1+slope^2) and accumulating each block. Each direction template keeps the original floating-point expression and operation order. The general CUDA kernel is visible in joseph_kernel.cu; it does not call any ASTRA binary or API. Rays with positive projected support receive its reciprocal; all other rays predict zero. Input angles convert degrees to float64 radians and then float32 radians as in the source geometry.

For each ray the normalized measured direction k=g/(norm(g)+1e-12) yields six contraction weights S=(kx^2,ky^2,kz^2,2*kx*ky,2*kx*kz,2*ky*kz). W equals 1/noise_std when nonzero, zero otherwise, then divides by its maximum. The measured weighted right-hand side is b=W*strain_measurements. The exact source objective is the unnormalized sum of squared residuals:

```math
f(a)=\|WSPBa-b\|_2^2,\qquad \nabla f(a)=2J^{\mathsf T}(WSPBa-b).
```

a contains all six sets of 65 coefficients, component first. J is the matched bound RBF Jacobian: project all 65 basis functions through the same P, multiply by each component's W*S, and concatenate six blocks, giving (96000,390), float64. Forming J uses the original float32 forward before float64 weighted matrix multiplication. It is the transpose of this same discrete RBF model, not the source's unmatched GPU image backprojection. Float32 forward evaluation is approximately linear to its rounding precision; independently tested bound finite differences quantify the gradient accuracy.

This is a named correction: the original source GPU backprojection is not its Joseph forward transpose. Full impulse and bound finite-difference checks show a 15.1% image-adjoint discrepancy and large actual objective directional-gradient errors. The corrected source oracle replaces only the backward function with J transpose, retaining data, original GPU forward, RBF basis, objective, weights, initialization, optimizer and stopping. This cleaned implementation reproduces that corrected oracle exactly. It does not claim unchanged reproduction of the erroneous gradient. Original default GPU and CPU source outputs remain separately identified for scientific comparison.

Initialize all 390 coefficients to zero. Use scipy.optimize.minimize L-BFGS-B with jac=True, tol=1e-8, maxiter=390 and otherwise original defaults. The original utils.lsq ignores its caller tol argument and hardcodes 1e-8; the local implementation preserves the effective value. No additional regularizer, positivity constraint, line-search modification or early stopping is introduced. The default source stops after108 iterations by relative function reduction, not gradient convergence. The exact returned message, objective and full evaluation history are recorded. Optional maxiter changes in the notebook are explicitly convergence diagnostics.

CPU and simplified GPU arithmetic that perturb interpolation-bin boundaries can shift a poorly conditioned inverse by about one percent despite small forward differences. The final CUDA direction templates and accumulation are therefore preserved without algebraic simplification. Original full-size stages, projected basis, final field and coefficients are tested for exact equality on the validated host. Independent axis-aligned sums, tensor contractions, matched adjoint inner products, and multi-direction bound finite differences test the mathematics separately. A CPU near-equivalent and original CPU strip output are diagnostic comparisons, not accepted standard output.

Evaluation uses independently supplied author simulation truth, all six full arrays including zero outside support. Each component has cosine NCC and dynamic-range NRMSE, no scale or alignment. Boundaries are .9 times the corrected oracle NCC and1.1 times its NRMSE, justified by its good per-component errors; no loose reference-parity threshold is used to hide operator differences. Reference arrays, original/corrected method results, and fresh results are distinctly identified.
