# Shipped interfaces and execution flow

The standard entry point is `python -m src.main`. Importing `src.main` does not change a Matplotlib backend or run reconstruction. It uses task-relative default paths, independent of the current working directory. Explicit callable path arguments are caller-relative. The standalone evaluator is `python evaluation/judge.py --prediction output/reconstruction.npz --report output/judge_report.json` and imports no reference solver modules.

`src.main.run(data_path=None, output_path=None)` loads the visible NPZ with pickle disabled, removes only the leading batch dimension, calls preprocessing and reconstruction, creates the output directory, and writes real float64 `reconstruction` and `standard_error`, each `(1,11310)`, in A m² T⁻². It returns the complete fresh diagnostic dictionary plus `runtime_seconds`. No checkpoints or hidden arrays enter this caller flow.

`src.preprocessing.preprocess(raw, slope_percent=70.0)` consumes five float64 vectors `(15504,)`: `field`, `reversal_field` in T, `moment` in A m², and dimensionless `curve_index`, `point_index`. It copies arrays, computes the actual last-curve field increment and performs high-field correction, opening-field detection, and lower-branch subtraction. It returns a state dictionary containing `H`, `Hr`, `M`, `Fk`, `Fj`, `dH`, `Hopen`, `DM`, and the high-field configuration object. All domain observations remain. Its local numerical stage functions `slope_correction(state)`, `find_Hopen(state,dMlim=0.05)` and `lowerbranch_subtract(state)` retain the source's explicit mathematical loops. These stage functions update and return their input dictionary. `M` is high-field corrected; `DM` also has the lower branch removed.

`src.physics_model.design_matrix(field,reversal_field)` returns `(N,10)` float64 polynomial basis columns in the documented order. `local_response(coefficients,field,reversal_field)` evaluates a six- or ten-parameter local moment surface, returning `(N,)` A m². `mixed_derivative_density(coefficients)` returns the scalar quadratic signed density in A m² T⁻². These functions expose the acquisition model and derivative for independent mathematical tests.

`src.solvers.reconstruct(state,smoothing_factors=(2.,3.,4.,5.,7.,10.),scoring_count=2000)` consumes the preprocessed state and returns `(11310,)` density and SE arrays, `(11310,4)` log evidence and probabilities, `(K,4)` smoothing score counts for K candidates, the selected scalar smoothing factor, `(2000,)` scoring observation indices, `(11310,)` native domain observation indices and `(11310,)` diagnostic p values. It has no filesystem or plotting side effects. Neighbor selection always uses every input observation, including positions outside the reporting domain. The domain is determined from acquisition coordinates before fitted values exist.

The explicit numerical helpers `OLS2BF(X,y)`, `Bayes_factor(N,R2,order=1,B=0)`, `OLS_pts(sc0,sc1,lamb_sc,sb0,sb1,lamb_sb,Hc,Hb,dH,Hc0,Hb0)`, `vari_s(s0,s1,lamb,H,dH)`, `vari_T(u,s)`, `vari_W(Hc,Hc0,Hb,Hb0,dH,Sc,Sb)` and `vari_weights(...)` implement evidence, smoothing windows and tapered regression weights. `inv_jit(a)` and `dot_jit(a,b)` are ordinary NumPy linear algebra compatibility names; no JIT or domain library is used. All helper units follow the physical arguments: field inputs are T, smoothing factors dimensionless, weights dimensionless, moment observations A m². Their source origin and direct fixtures are mapped in validation.

`src.visualization.metrics(estimate,reference)` returns scalar standard NCC/NRMSE and rejects degenerate references. `density_plot(ax,state,result,title=...)` plots measured native positions in mT; color values are density times 1000, with no synthetic filled grid. `local_consistency(state,result)` returns center moment predictions, measured-minus-predicted residuals in A m² and local rectangle-integral errors in A m². It explicitly distinguishes local derivative consistency from a unique global moment inversion. The module imports pyplot normally and never selects a backend.

The active review notebook loads raw acquisition data and calls `run()` for the fresh standard path, then runs current modules for fixed-smoothing, preprocessing and additional-noise comparisons. Upstream arrays are loaded only as labeled comparisons. Images, tables, residuals and actual runtimes arise from these computations. The notebook uses source modules only; no private upstream checkout is imported. Hidden `notebooks/reference_outputs/` contains independently identified upstream method measurements and a labeled fresh standard measurement for provenance, not solver input or reconstruction caches.

`evaluation/judge.py` resolves hidden assets relative to itself, validates every required key/shape/dtype/finite value and nonnegative SE, validates nondegenerate references and finite nonvacuous thresholds, then independently computes metrics. Malformed input or evaluator failure yields status error, empty metrics and exit 2; valid low quality gives fail/exit 1; pass gives exit 0. Its CLI creates the report parent directory and diagnoses report-write failures on stderr. `ground_truth.npz`, if independently supplied in a future evaluator, takes precedence over the current method reference; none is invented here.

All tests, fixtures and authoritative validation evidence are under `test/`. Original source, author data containers, PDF, capture scripts, oracle environment and logs remain outside this task directory in the private archive. The runtime depends only on pinned NumPy, SciPy and Matplotlib; pytest/Jupyter are shared development tools.
