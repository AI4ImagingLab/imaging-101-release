# Interfaces and actual execution

Standard entry point `python -m src.main`: current task workspace -> preprocessing.load_data(data/raw_data.npz) -> solvers.reconstruct(counts,irf) -> output/reconstruction.npz. Only key reconstruction float64(1,50,50), signed relative apparent range in mm, is a submission. All arrays use batch-first storage; internal calculations drop the single batch. Main creates output when needed. No imaging library, upstream import or cross-task code is used; no library changes the plotting backend.

preprocessing.normalize_irf(raw) accepts one-dimensional nonnegative finite numeric counts, requires positive sum, returns peak-zero float64(N,) unit-sum h. load_data(path) requires uint32(1,50,50,10000) photon_counts and float64(1,10000) instrument_response, allow_pickle=False; returns counts(50,50,10000),h(10000,). It performs no target normalization or count masking.

physics_model.expected_histogram(irf,shift,signal_photons,background_per_bin) evaluates the explicit circular pulse plus uniform background and returns expected counts(N,). shifts_to_depth(shifts,time_bin_s=1e-12) subtracts shifts[0,0], returns float64 mm with matching spatial shape. fit_nuisance(hist,irf,shift) returns (A,b,model), fitted nonnegative signal photons/background counts per bin and float64 diagnostic expected counts. It is used by review plots, never reconstruction peak updates.

solvers.zero_norm(a) converts to float64 and normalizes the final temporal axis. circular_correlation(signal,template) returns float64 normalized correlation with shape matching broadcast signal; rejects mismatched final lengths. matched_peaks(histograms,irf) returns int64 spatial/batch peak indices and the float64 correlation array. reconstruct(counts,irf) requires bound shapes and returns (float64(50,50)mm,int64(50,50)bins), computing one50-histogram row at a time. There are no file side effects, optimizer iterations or hidden settings.

visualization.review(task_dir,figure_dir) actively runs the bound inverse, independently evaluates it and computes labeled comparisons: original vs fresh, raw-bin maxima, actual temporal-bin aggregation sensitivity, actual multipath and low-count examples, and circular-vs-linear boundary diagnostics. It exports five PNG/SVG/PDF groups with numeric_sources.npz, metrics.json and manifest.json to the notebook environment IMAGING_FIGURE_DIR. Original maps load only from notebooks/reference_outputs/upstream_methods.npz and are labeled as original, never fresh.

evaluation/judge.py is standalone NumPy and does not import src or submitted code. It resolves hidden references relative to its own path, prioritizes ground_truth.npz if present, and validates exact finite float64(1,50,50), required key, gauge, integer bins and acquisition-window consistency. It independently reopens the public calibration/counts and recomputes all candidate correlation values with its own FFT implementation. Boundary configuration rejects bool, nonfinite or out-of-range values. Reports contain status/pass/metrics/comparison boundaries/errors, exit0 pass,1 valid below thresholds,2 input/evaluator error. Errors have empty metrics. Report directories are created, write failure returns2 with stderr. Test fixtures and private capture provenance are documented in test/validation.md; no full source checkout is packaged.
