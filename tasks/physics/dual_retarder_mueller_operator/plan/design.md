# Shipped interfaces and flow

Runtime contains explicit NumPy optics and matrix inversion, with Matplotlib only for review plots. No Katsu, other domain package, upstream source, pretrained model or cross-task module is imported by src/generator/tests/Judge/notebook. All needed known calibration constants are explicit in preprocessing and README. Original software remains in a separate private oracle directory.

`preprocessing.load_data(path='data/raw_data.npz')` requires complete `(1,24)` angle/power arrays, checks finite values, removes the singleton batch and returns two1-Darrays. Module constants are analyzer/generator speed ratio5, retardanceπ/2, and both fixed polarizer axes0. Angles are radians and power is relative to unit known incident intensity.

`physics_model.linear_polarizer(angle)` accepts scalar/array orientations and returns shape angle.shape+(4,4),real float64, with physical one-half transmission. `linear_retarder(angle,retardance)` broadcasts angle/delay arrays and returns their shape+(4,4), preserving the native circular handedness.

`acquisition(angles,angular_increment=5.,psg_retardance=pi/2,psa_retardance=pi/2)` returns `(generator,analyzer,design)`, shapes `(N,4,4)`, `(N,4,4)`, `(N,16)`. Known polarizer axes are0. Design entries are explicit analyzer-row/generator-column outer products in row-major sample order. `forward(mueller,angles,angular_increment=5.,psg_retardance=pi/2,psa_retardance=pi/2)` returns the Nrelative-intensity values for a real4×4matrix. `adjoint(power,angles)` returns the4×4algebraic transpose under default known calibration. `coherency_matrix(mueller)` returns4×4complex128Hermitian diagnostic; its eigenvalues/known cases are tested independently. The required benchmark output remains real; no complex-to-real coercion is accepted by the Judge.

`solvers.reconstruct(angles,power,rcond=1e-15,psg_retardance=pi/2,psa_retardance=pi/2)` computes local optical design, full reduced SVD, explicit reciprocal-singular-value inverse and the complete sample matrix. It returns `(output,diagnostics)`. Output has one real float64`reconstruction`array `(1,4,4)`. Diagnostics contain generator/analyzer/design, inverse `(16,N)`, singular values `(min(N,16),)`, retained rank, numerical condition, predicted intensities and residuals `(N,)`. There are no iterations or hidden inputs. The same routine supports the original16measurement comparison and explicitly labeled sensitivity experiments.

`generate_data.author_example(seed=20261026)` returns a raw batch-first angle/power dictionary and true4×4sample matrix, using the original author sample family and acquisition with local optics. It is hidden maintainer reproduction logic, documented in its module docstring, and is not called by main or exposed as solver calibration. Independent upstream fixtures are generated by original code before extraction, never by this helper. The task-bound original raw/truth assets are not overwritten during ordinary execution.

`main.run(data_path='data/raw_data.npz',output_path='output/reconstruction.npz')` calls load_data/reconstruct, creates the output parent, writes only the required NPZ and returns `(output,diagnostics,elapsed_seconds)`. `python -m src.main` invokes this standard active path. Importing main never changes a Matplotlib backend. `visualization` functions take already computed arrays and supply observation/matrix/rank/noise comparison figures; they do not read a hidden answer or run an upstream solver.

The active notebook freshly calls run on the complete bound24angle acquisition and separately reconstructs the original16angle acquisition from its labeled comparison asset. The hidden actual synthetic sample is loaded only for maintainer truth plots/metrics, never for reconstruction. Fresh sampling, calibration and noise alternatives call the same local inverse. Original comparison matrices are loaded only for upstream-parity overlays, with measurement counts/roles identified explicitly.

`evaluation/judge.py` imports only standard library/NumPy. It resolves `ground_truth.npz` and `metrics.json` relative to its own file, uses actual truth even if a baseline-reference file exists, and resolves public calibration from the sibling data path. `predict_intensity` derives generator/analyzer Stokes vectors directly from scalar trigonometry, independently of the solver's Mueller-matrix construction. Required shape/dtype/finiteness/key checks precede scoring. Invalid/evaluator inputs produce empty metrics/statuserror/exit2; valid poor predictions fail/exit1; passes exit0. CLI report paths are caller-relative, parents are created, JSON is UTF8with no NaN/Infinity, and report-write failures diagnose stderr/exit2. The evaluator never imports source or executes submitted code.

Frozen original16/24fixtures under test/fixtures are consumed by stage/full-pipeline parity tests. The corresponding two notebook reference assets preserve distinct original acquisition conditions. The actual hidden synthetic sample is not labeled as a method reference. Test cases verify native optics/design/inverse, independent Jones/handedness/cone/coherency physics, all16output scoring, known metric values, malformed files and CLI behavior. All complete original sources, paper PDFs, original notebook execution logs/figures, seeds and environment captures remain outside this task directory.
