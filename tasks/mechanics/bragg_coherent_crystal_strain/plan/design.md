# Shipped interfaces and execution flow

This document describes the local implementation, including its diagnostic interfaces. The selected reconstruction is two complete experimental volumes, 200 independent starts per volume, 1020 updates per start, and an aligned average of the ten lowest final-error starts. A shorter diagnostic run is not the standard task. Completion evidence and unresolved gates are recorded in `test/validation.md`; this document does not certify unexecuted runs.

## Files, ownership and coordinate convention

The standard entry point is `python -m src.main` from the task directory. Relative CLI paths resolve from the caller's working directory. The CLI reads only `data/raw_data.npz` and explicit acquisition constants in `src/preprocessing.py`. It neither opens hidden reference arrays nor imports an upstream package. It creates the parent of its requested output path and writes one compressed NPZ. No root-level wrapper is provided.

Public counts retain their original121-plane detector coordinates. Complete source preprocessing applies explicit auto threshold, square root, even-fast padding121to126 (left2/right3) and peak centering, in that order. Iterative density, support, PC ROI and predictions use the centered126 grid. Physical comparison inverse-rolls after finite linear convolution and extracts indices2:123 to retain all original counts. These operators cannot be interchanged. Object alignment for averaging is a separate operation.

`src/preprocessing.py` owns observation validation and nominal geometry. `src/physics_model.py` owns pure CPU forward, inverse, coherence and strain mathematics. `src/solvers.py` owns numerical backend primitives and the explicit iterative protocol, initialization, selection and averaging. `src/main.py` owns argument parsing, progress and serialization. Importing these modules does not choose a Matplotlib backend or launch reconstruction.

## Observation and geometry interfaces

`load_observations(path="data/raw_data.npz") -> (counts, theta)` opens the archive with `allow_pickle=False`. Required input arrays are `photon_counts: int32[1,2,121,256,256]` and `theta: float64[1,2,121]`. It validates exact shapes/dtypes, nonnegative counts and finite angles; invalid inputs raise `ValueError`. Returned batch-stripped shapes are `(2,121,256,256)` counts and `(2,121)` degrees. No normalization, crop, background subtraction or array reordering occurs.

`measured_amplitude(counts) -> float32[...]` computes raw square-root counts for diagnostic/physical comparisons. `center_diffraction_peak(amplitude) -> (rolled, shift)` preserves dtype/shape and uses first C-order maximum. `prepare_observations(counts) -> (amplitude,metadata)` is the actual reconstruction preprocessing: validate finite nonnegative3D counts with positive sum, compute `max(2,.141*mean(nonzero)-3.062)`, clear counts at or below it, float64 square root, even-fast zero padding, center and float32 output. For the bound input, amplitude is `(126,256,256)`. Metadata contains `intensity_threshold:float` in counts, `padding:tuple[3]` of integer pairs and `peak_shift:int64[3]`. P1/P2 shifts are `(1,-19,-3)` / `(0,-49,-3)`. Inputs are not modified. `RECONSTRUCTION_SHAPE=(126,256,256)` is the default shape of `real_space_basis`; `SHAPE=(121,256,256)` continues to validate raw acquisition inputs.

`reciprocal_geometry() -> (B,q)` returns float64 `(3,3)` reciprocal increments in rad/nm per stored index and `(3,)` scattering vector in rad/nm. Rows are laboratory outboard/up/downstream, columns are rocking/row-down/column. Constants match the README: 9 keV, 2.8 m, 55 micrometer pixels, detector angles28.488 and0.0478 degrees, rocking increment0.002 degrees. `real_space_basis(shape=RECONSTRUCTION_SHAPE) -> float64[3,3]` evaluates `2*pi*inv(B).T@diag(1/shape)` in nm per index. These are nominal oblique coordinates, not a resampled orthogonal volume or absolute-strain calibration.

## CPU mathematical interfaces

`reciprocal_wavefield(obj)` is the centered positive-sign unscaled DFT `fftshift(ifftn(ifftshift(obj),norm="forward"))`. `direct_wavefield(wavefield)` is its inverse centered negative-sign DFT divided by voxel count. Both preserve spatial shape and compatible complex precision; the positive sign is deliberate. Inputs are a single three-dimensional volume without batch/position axes.

`full_convolution(array,kernel)` uses real FFT padding to at least `array.shape+kernel.shape-1`, then removes numerical padding. `linear_convolution(array,kernel)` crops the full result from `(kernel.shape-1)//2`, returning the array's shape. Boundaries are zero extended, with no circular convolution. Both accept real arrays in compatible numeric precision. `kernel_adjoint(residual,coherent,kernel_shape)` flips the coherent array, evaluates full convolution, and crops from `coherent.shape-1-(kernel_shape-1)//2`, returning the requested kernel shape. For an even kernel this is not the same crop as the forward operator.

`crop_center(array,shape)` returns a view with per-axis start `(old-new)//2`. `amplitude_projection(wavefield,amplitude,kernel=None)` returns a modified complex wavefield and Python float squared-relative amplitude error. With no kernel its denominator is the wavefield magnitude; otherwise it is the square root of nonnegative finite convolution of intensity. Ratios are zero below the absolute `1e-9` amplitude cutoff. This PC amplitude-ratio operation is a heuristic constraint update, not an exact proximal operator.

`update_coherence(amplitude,previous,measured_roi,kernel,iterations=20)` crops the current amplitude to kernel shape, forms the extrapolated amplitude, normalizes its intensity to the measured ROI photon sum, and explicitly performs finite-window multiplicative kernel updates. The transpose sensitivity is included; small denominators use `1e-30`, negative FFT roundoff is clamped, and the returned real kernel has unit mass. `shrink_support(obj,sigma,threshold=0.1)` returns an integer mask after reflect-boundary Gaussian smoothing with radius `floor(4*sigma+0.5)` and a greater-than-or-equal threshold.

`observation_intensity(obj,kernel)` returns nonnegative centered predicted counts, same shape as density. `raw_observation_intensity(obj,kernel,peak_shift,padding=None)` validates one shift per axis, inverse-rolls after convolution, then removes the supplied padding pairs. Benchmark callers pass preprocessing metadata padding `((2,3),(0,0),(0,0))`, obtaining original121-plane counts; omission is a generic unpadded diagnostic option. `projected_strain(obj,basis_nm,q_vector,support_fraction=exp(-1)) -> (strain,valid)` returns float64 relative projected strain and Boolean interior mask, eroded by a full3-cube. Central complex-ratio differences require two-step phase change within the principal interval. The valid-interior mean is removed; exterior iszero. No full tensor, refraction correction or electric field is inferred.

## Numerical backend and iterative interfaces

`ArrayBackend(device="cpu")` provides array transfer, centered FFT, finite convolution, exact kernel transpose, Gaussian smoothing, flip and nonnegative square root. CPU uses NumPy/SciPy. `device="cuda"` uses PyTorch CUDA primitives with explicit reflected separable Gaussian convolution. `device="cupy"` uses optional generic CuPy/CuPyX FFT, convolution and Gaussian primitives. It never invokes a diffraction reconstruction API. Exact backend compatibility is a measured validation gate: a finite result from a different backend alone does not establish full nonlinear trajectory parity.

`initial_object(shape,amplitude_max,seed) -> (image,support)` returns complex64 random density and float64 centered half-box support. A NumPy default generator draws float32 real/imaginary uniform components, multiplies their complex array in place by its float32 squared norm times peak amplitude, and masks in place. This unusually large historical scale is preserved. The first ER support multiplication promotes the trajectory to complex128. The initial PC kernel is float64 `0.5`: the upstream GPU `full` wrapper ignores its passed dtype keyword, so this preserves actual executed precision rather than the apparent call-site dtype.

`reconstruction_step(image,support,amplitude,hio=False,beta=0.9,kernel=None)` provides one CPU update for stage tests, returning image and error. `reconstruct_one(amplitude,seed=0,device="cpu",initial=None,iterations=1020,progress=None,stage_callback=None)` returns max-magnitude-normalized complex density, coherence kernel and float64 error history. `initial` injects a hidden numerical fixture for tests only; it is not loaded by CLI execution. `iterations` in `[1,1020]` permits stage diagnostics. Normal reconstruction uses the default 1020. The progress callback receives `(step,error)` every 100 updates. Optional `stage_callback(step,image,support,kernel,error,backend)` receives the current single-volume backend arrays after every completed update for hidden numerical tests; it must not mutate them. No checkpoint or precomputed result is read.

Each start has five cycles of 20 ER and 180 HIO, followed by 20 ER. HIO feedback is 0.9. Shrink-wrap sigma is 3, 2.5, 2, 1.5, 1 for the cycles, using threshold 0.1 and the upstream trigger schedule. Partial coherence begins at update index 400; kernels are updated every 50 steps with 20 inner multiplicative updates on a central 16-cube. Previous projected amplitudes are recorded immediately before each PC update. The stored error is computed before the current amplitude/real-space update, so the last ranking error is not the recomputed residual of the returned post-ER/max-normalized object. Output forward residuals are separately identified. Kernel estimation, amplitude projection and support updates remain explicit local mathematics.

`align_complex(reference,candidate) -> (aligned,parameters)` compares the candidate and its conjugate-flipped twin, computes complex cyclic correlation, chooses the largest correlation magnitude, rolls by an integer displacement and fixes a constant phase. The returned metadata contains `twin` and a three-index `shift`; no continuous deformation or fitted phase ramp is used. `aggregate_ensemble(objects,kernels,amplitude)` aligns objects to the first selected estimate, averages complex objects and kernels separately, and restores photon scale using the public amplitude least-squares scalar. It returns scaled object, unit-mass kernel and alignment metadata.

Complex averaging now uses `objects[0].copy()`, selected-order in-place additions, then division by `len(objects)`. The interfaces, alignment traversal, kernel `mean`, photon-scale restoration and returned arrays are unchanged. The current `reconstruct` additionally stores its freshly computed selected objects in temporary disk files and uses `StoredObjects` for this same reduction; this replaces the historical1.321GB resident list. The first-object anchor132120576B, accumulated result132120576B, current candidate132120576B and alignment/FFT/twin temporaries still require explicit budgeting. See the lifetime interface below.

These ensemble interfaces implement the released variant's explicit ten-result discrete-grid convention. Article Methods states200 starts, selection and correlation, but its exact historical selection count/alignment/averaging is unverified. Upstream `align_arrays_subpixel` (magnitude registration in GA breeding) and `Rec.average_operation` (within-run amplitude accumulation) are distinct operations and are not claimed as source parity for this local ensemble. The private full-run source driver plus independently written aggregator supplies numerical comparison for the selected convention only.

The review path retains these ambiguities together with structured raw-count residuals, weak-tail mismatch, secondary density lobes and inferred-kernel complexity. These are limitations of physical interpretation rather than quantities silently removed through masking or fitted display scaling. `observation_figure` returns one six-by-three-panel figure: measured, predicted and signed-symlog residual projections over each of three axes, for both positions. Measured/predicted pairs share a count logarithmic scale; prediction is mapped to all original121 planes with declared inverse shift/pad removal. This review does not certify published morphology or absolute strain.

`reconstruct(counts,starts=200,device="cupy",progress=None)` receives `(2,121,256,256)` raw counts. Each position passes through `prepare_observations`, runs seeds `10000+1000*position+start`, ranks by final thresholded126-grid error then index, and keeps ten objects. All starts execute. Returns `complex128[1,2,126,256,256]` density, `float64[1,2,16,16,16]` kernels and per-position dictionaries of errors, selected indices, alignments, peak shift, threshold and padding. Fewer than ten starts are rejected; benchmark caller always requests200. Callback receives `(position,start,error,seconds)`.

## Serialization and review boundary

`main(argv=None)` accepts `--data`, `--output`, `--device` (default `cupy`) and optional maintainer `--measurements`; it prints per-start progress and total wall time, creates the output directory and writes only the declared `reconstruction` and `coherence` submission keys. It casts these to complex128 and float64 at serialization. It does not equate the submission with truth. The standalone evaluator, notebook comparisons and frozen upstream stage fixtures are maintainer materials and are not solver inputs. Actual full-run and notebook evidence must be added to `test/validation.md` before completion; source descriptions or cached oracle measurements do not replace those runs.

The optional measurement path is created only when requested; its NPZ stores `errors:float64[2,200]` for the thresholded126 objective, `selected:int64[2,10]`, `peak_shifts:int64[2,3]`, `intensity_thresholds:float64[2]` in counts, `padding:int64[2,3,2]`, and scalar float64 `seconds`. The notebook requests this identified fresh measurement file. It supplies no oracle arrays to the solver. The generic CuPy allocator pool is capped at3 GiB; external FFT workspace is monitored separately.

## Evaluator and visualization interfaces

`evaluation/judge.py` is standalone and imports only standard-library, NumPy and SciPy numerical primitives. `load_arrays(path)` requires exact complex128/float64 submission shapes and finite values, with no reshape or coercion. `validate_thresholds(thresholds)` checks exact metric names, finite non-Boolean boundaries, correct directions and nonvacuous ranges before scoring. `validate_metric_specification(specification)` requires those nested rules plus exactly matching flat `p1_*_boundary` and `p2_*_boundary` numeric entries in the boundary file; missing, extra, nonfinite, Boolean or conflicting flat boundaries are evaluator errors. It returns the validated nested rules, so there are no conflicting threshold values. `validate_reference` rejects zero/invalid reference norms, invalid probability kernels and nonpositive/negative acquisition counts. `score_arrays(prediction,reference,counts)` returns per-position complex relative L2, complex cosine, kernel relative L2, kernel mass error, negative kernel mass and full-volume physical amplitude residual. Its independent `align_to_reference` permits only the public symmetries. `evaluate(path)` returns report and exitcode; `main(argv)` writes UTF-8 finite JSON, makes report parents, and returns0/1/2 for pass/fail/error. Hidden paths resolve from the judge file; CLI prediction/report paths retain caller-relative meaning. All16 prospective boundaries are frozen and all15 actual bound-reference controls passed their expected exit; reference self-consistency is separately identified from physical accuracy. Full fresh400 evaluation remains pending.

`src/visualization.py` returns Matplotlib figures without selecting a backend or saving implicit files. `density_phase_figures(reconstruction,label="Fresh cleaned reconstruction")` returns an amplitude/phase figure dictionary. It plots maximum-amplitude projections and phase slices through the actual density maximum, with index/axis labels; phase is masked below0.1 relative amplitude. `strain_figure(reconstruction)` likewise slices through the density maximum so an arbitrary translation does not produce empty array-center panels. `support_boundary_figure(reconstruction,maximum_points=15000)` plots sampled boundary voxel centers at fixed levels1/e,0.5,0.6 in nominal laboratory micrometers. Its3D box aspect follows the physical coordinate ranges, so equal micrometer lengths have equal display scale. `observation_figure(reconstruction,coherence,counts)` inverse-rolls/crops finite blurred predictions and compares rocking-integrated counts against all original121 raw planes, with no threshold mask. `coherence_figure(coherence)` plots three central kernel planes. `ensemble_error_figure(upstream_errors,fresh_errors)` compares the separate all200-start thresholded objectives for each position. Density inputs use `(1,2,126,256,256)`, kernels `(1,2,16,16,16)`, raw counts `(2,121,256,256)`, and start-error arrays `(2,200)`. Plot sampling affects only displayed boundary points; reconstruction and metrics retain every voxel.

### Independent phase and strain scoring interfaces

`reference_masks(reference)` accepts one complex3D volume and returns Boolean phase/interior masks of identical shape; empty eroded support raises ValueError. `nominal_strain_coefficients(shape)` returns float64[3], dimensionless per index-phase increment, from independently implemented nominal q and D. `relative_projected_strain(obj,interior)` returns float64[n_valid], mean removed on the supplied fixed mask. It indexes only the six valid neighbor sets and accumulates one axis at a time, avoiding three full gradient volumes. `phase_strain_errors(aligned,reference)` returns two Python floats: wrapped phase RMS in radians and nominal relative projected strain RMS dimensionless. Predicted zero phase is penalized by pi; no predicted voxel is removed. `score_arrays` adds both metrics for both positions, for16 metric values total. No helper imports the solver. ### Fresh selected-object storage and lifetime

`StoredObjects(paths)` accepts the ordered paths of this run's selected temporary NumPy files containing complex128 arrays. Index0 lazily loads/caches the fixed anchor; slicing yields a generator loading one candidate at a time. The standard `reconstruct` writes qualifying freshly computed objects via NumPy serialization into a `TemporaryDirectory(prefix="bragg-fresh-selected-")` outside the task. No archived reference/result is read. Top10 ranking remains finalnativeerror then startindex; evicted paths are immediately removed. At each position only the anchor, current candidate and CPU aggregation temporaries are resident instead of ten original objects. All temporary files are removed on success or Python exception when the scratch context exits. Raw/ground/reference deliverables remain NPZ.

At the position boundary all1020-step start-local GPU arrays have died; only then the generic CuPy FFT plan cache and unused device/pinned pools are cleared before the CPU-only ensemble aggregation. This changes allocation lifetime, not arrays, seeds, arithmetic, support/kernel updates or run counts. The result and alignment order remain identical; both actual selected10 proofs are recorded in validation, while full fresh runtime remains pending. P2 retains P1 aggregated result132120576B. Final stacking/NPZ output remain unchanged. Notebook drops intermediate full arrays and closes displayed figures, then runs the independent Judge after releasing the upstream comparison array.

Final `np.stack(output)[None]` momentarily retains the two-array result list264241152B plus new stack264241152B; CLI dtype-preserving `astype` can add another264241152B during NPZ serialization. This is included in the execution budget; selected scratch arrays have been removed when `reconstruct` returns.
