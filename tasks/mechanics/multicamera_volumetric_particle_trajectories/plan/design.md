# Shipped execution and interfaces

Runtime requirements are NumPy2.4.6, SciPy1.17.1, Matplotlib3.11.1 and Python standard library. Windows x64 MSVC19.29 C++17 is an explicitly validated CPU environment exception for readable local numerical kernels; no original OpenLPT package, TIFF reader, nanoflann, Eigen, OpenMP, upstream headers/binaries or runtime download is used. Source is embedded as KERNEL_SOURCE in physics_model.py. The temporary content-addressed compile cache is outside the task; /O2 /MD /fp:strict and exact source hash identify it. A missing compiler causes a descriptive error. First-use compilation is measured separately from warm numeric runtime.

`python -m src.main` defaults to data/raw_data.npz and output/reconstruction.npz relative to caller cwd; --data/--output accept explicit paths. It loads observations, actively reconstructs all100frames and writes only the declared submission NPZ. Importing main never changes a notebook backend. No reference output is read by any solver module.

`preprocessing.load_data(path)` returns a dictionary with the seven exact batched observation/calibration arrays; shapes/dtypes/ranges and finite calibration are checked. `camera_parameters(data)` concatenates K,R,Rinverse,t,C,distortion to contiguous float64(4,38), preserving supplied signs/inverses.

`physics_model.library()` returns the locally compiled ctypes library and initializes strict pointer signatures. General C++ numerical operations implement detection, camera models, PSF estimation, triangulation, candidate competition, coordinate refinement, residuals, displacement fields, adaptive prediction and track bookkeeping. They are flat free functions and simple numeric data structs, not copies of the upstream framework/class hierarchy. C exports numeric_project/rays/detect/otf/match/shake/residual/field/predict/ipr/tracking each call owned numeric functions. All compiled source is reviewable in this module. MSVC compiles only this string and standard headers.

Python `project(points,camera)` takes float64(N,3),float64(38) and returns(N,2)pixel coordinates. `rays(points,camera)` returns(N,6) origin_mm then unit direction. `detect(image,threshold=30)` takes a2D numeric image and returns(N,2)subpixel column,row. `estimate_otf(images)` takes(F,H,W) and returns float64(3) A[ADU],B/C[pixel^-2]. `predict(history)` maps float64(L,3),L≥3 to float64(3)mm. `refine(positions,images,cameras,otf,active_mask=15)` takes(N,3),(4,1024,1024),(4,38),(4,3) and returns fresh positions,scores(N),int32flags(N). Bit0 means ghost and bit1 repeated. It copies input positions. `residual` accepts the same physical arrays and returns nonnegative IPR residual images. `reconstruct_frame(images,cameras,otf)` runs all full/reduced IPR passes and returns variable(N,3).

`solvers.reconstruct(data)` returns `(submission,diagnostics)`. Submission contains float64 positions(1,N,3),int16 frame_index(1,N),int32 track_id(1,N). Diagnostics contain freshly estimated otf(4,3),statistics(100,4) and elapsed runtime_seconds. Statistics columns are newIPRpoints,longactive,shortactive,inactive+exited. Internal allocation of2million rows is capacity only; overflow raises rather than truncates. All100frames/four cameras are used. Native segment labels are arbitrary; final category groups get separate global labels.

`visualization.segment_velocity(positions,frames,ids)` returns consecutive-row index pairs and displacement(mm per1second). `gaussian_smooth_tracks(...,sigma=1)` performs an explicitly labelled diagnostic smoothing, radius3sigma and nearest boundary; it never replaces submitted raw reconstructed points. Library imports do not set Matplotlib backend.

Standalone evaluation/judge.py imports no solver module. read_tracks validates all keys/dtypes/rows, finite values, frame0..99, nonnegative IDs and unique(ID,frame). Actual truth must lie in the known cube; reconstructed estimates are not clipped or rejected merely for overshooting it. read_limits rejects invalid numeric/range configurations. evaluate(prediction_path,asset_dir=HERE) prioritizes actual ground_truth.npz; invalid truth cannot fall back. `measure` computes all five full-field/full-time metrics and optional identified correspondence diagnostics. Reports have status,passed,metrics,thresholds,errors; malformed input yields empty metrics and CLI2, scientifically poor valid output CLI1, pass CLI0. Reports are UTF8 finite JSON. Hidden paths resolve from evaluator file; caller prediction/report paths remain caller-relative.

Numeric fixtures contain98 arrays from a completed output-only capture of the qualified full native run, frozen before local shake code. Tests consume detector/calibration/stereo/shake/initialframe/LMS cases. Reference outputs retain unchanged and qualified full-source row tables; these are comparison data, not solver inputs or truth. evaluation/ground_truth.npz contains the independent author manifest. The full notebook actively invokes reconstruct on public observations, evaluates fresh output, compares actual source runs, and computes real operator/trajectory/sensitivity diagnostics. Its cache-preview option, if used interactively, is explicitly labelled and does not satisfy active execution. Final canonical notebook is actual nbconvert output with explicit shared-Python kernel and embedded inline figures.


Additional notebook-only interfaces: `stereo_diagnostics(points,cameras,tolerance=.8)` accepts four float64(Nc,2) column,row detection lists and float64(4,38) camera parameters. It returns float64(M,5) candidate camera IDs plus ray RMS in mm, float64(S,4) selected ID tuples and float64(S,3) positions in mm. IDs use -1 for an inactive camera; allocation capacity100000 is checked by the numerical export. `triangulate_candidates(points,cameras,candidate_ids)` takes integer(M,4) ID tuples, forms each ray projector and returns float64(M,3) mm using a general linear solve; this diagnostic helper is not substituted for the source-convention triangulation in the standard tracker. `src.main --diagnostics PATH` optionally writes newly computed OTF, statistics and runtime for maintainer review. The default main writes only the required submission. These helpers never read hidden truth or comparison outputs.
