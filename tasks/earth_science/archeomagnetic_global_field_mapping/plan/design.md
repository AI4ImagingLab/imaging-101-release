# Shipped interfaces and execution flow

`python -m src.main` calls main(), loads only data/raw_data.npz, reconstructs all observations, evaluates maps, and writes output/reconstruction.npz with real float64 `reconstruction`(1,5,3,36,72) and `coefficients`(1,43,15). It returns the output Path and prints the final pre-update MAE. Imports do not select a Matplotlib backend.

`src.preprocessing.geodetic_to_geocentric(latitude,height=0.)` accepts radians and metres, returning geocentric colatitude radians, radius km, cosine and sine of the frame rotation. Broadcasting follows NumPy conventions. `load_observations(path=None)` defaults to the task-relative visible NPZ path. It returns(time,coords,value,sigma,kind), each withN=10044 rows; coords is(N,5)=(colatitude,longitude,radius,cd,sd), radians/radians/km/dimensionless/dimensionless. Observed values and sigma use nT forkind4(intensity) and radians forkind5(inclination) and6(declination). The returned order is intensity,inclination,declination and rows retain the source order within each group. Public storage remains degrees for directions.

`src.physics_model.harmonic_basis(coords,degree=3)` returns(N,3,(degree+1)^2−1) float64 geodetic north/east/down operator. It uses SciPy associated Legendre primitives, explicit Schmidt normalization, explicit derivative and radial factors, and explicit frame rotation. Coordinates must avoid exact geographic poles; the observations and grid do. `temporal_basis(time)` returns(N,43) cubic basis; out-of-interval times raise SciPy errors. `observables(coefficients,basis,temporal)` accepts(43,15),(N,3,15),(N,43), returning(N,7) X,Y,Z,H,F,I,D. Fields are nT, angles radians. `observable_jacobian(basis,prediction,kind)` returns(N,15) selected scalar-observable derivatives in the same physical conventions. `field_maps(coefficients)` returns(5,3,36,72) float64 geodetic field nT. Constants EPOCHS,LATITUDES,LONGITUDES,KNOTS define the public contract exactly.

`src.solvers.spline_overlap(first,second,count,step,derivative)` returns one scalar exact piecewise-polynomial overlap integral. `damping_matrices(degree=3,count=43,step=100.)` returns two dense(645,645) float64 quadratic forms S,T. `reconstruct(data,spatial_damping=1e-13,temporal_damping=1e-3,iterations=5)` returns coefficients(43,15) and a dictionary with `weighted_mae`(iterations,), `iterations`(iterations,43,15), and `predicted`(10044,). It creates no files. It uses locally implemented task objectives/Jacobians/updates and general SciPy Cholesky primitives; no upstream or domain modules are imported. The dense temporary Jacobian is approximately52MB and normal matrix3.3MB.

`src.visualization.metric_pair(estimate,reference)` computes the documented NCC/NRMSE independently of the Judge. `scientific_review(data,coefficients,diagnostics,upstream_original,upstream_corrected,export_dir=None)` generates six figure groups and actively recomputes three temporal-prior variants. It returns(figures,numeric,results); `figures` maps names to Matplotlib Figures, `numeric` contains exact plotted arrays, and `results` holds full precision numerical measurements. When export_dir is given, it writes PNG/SVG/PDF, numeric_sources.npz, metrics.json, and a SHA256 manifest there. Standard CLI does not call visualization. The notebook calls it for inline maintainer review; the separate private figure-export command chooses the maintainer archive output directory.

`evaluation/judge.py` is standalone and imports no solver code. Its `load(path)` validates both required keys/shapes/exact float64 dtype and finite values using allow_pickle=False. `metrics` computes deterministic cosine NCC and dynamic-range NRMSE, rejecting degenerate references. `evaluate(prediction)` returns(report,exitcode), with truth taking precedence if the reserved truth file exists; otherwise it selects the fixed baseline filename relative to its own script. Reference/machine-input failures return error, empty metrics, and code2; valid below-boundary predictions return fail/code1. `main(argv=None)` implements --prediction/--report, creates report parents, serializes finite UTF8JSON, and returns2 on report-write failure. CLI prediction/report paths use the caller working directory.

`test/fixtures/upstream_stages.npz` is consumed by upstream-parity tests, containing captured stage arrays on90 deterministic indices plus complete independent damping bands and five independent coefficient updates. `notebooks/reference_outputs/upstream_original.npz` and `upstream_corrected.npz` are consumed by the canonical notebook/visualization to distinguish the independent runs. Both contain coefficient histories, final coefficients, and original pre-update residual diagnostics. `evaluation/baseline_reference.npz` is the independent corrected oracle field maps and spline coefficients. These three consumers have distinct scientific roles; no array is relabeled ground truth.

All unit/metric/Judge tests are under test/unit_test. Independent stage, physics-pipeline parity and CLI/Judge integration are under test/comparing_test. The notebook actively calls reconstruct from raw observations and writes the declared fresh submission before evaluating it. It uses no upstream imports, does not read the baseline as a fresh result, and preserves independent-run, map, residual, coverage, convergence, and regularization comparisons. Private original source, papers, capture/build scripts, logs, and executed temporary notebook stay outside the task.

Judge observation_metrics(coefficients,path=PUBLIC_DATA) takes submitted coefficients(1,43,15), loads only public F/I/D observations and their times/coordinates/sigma, and returns three float RMS metrics. Its independent implementation derives geocentric coordinates from Cartesian ellipsoid geometry, evaluates harmonic-gradient components with SciPy lpmv and BSpline primitives, rotates into the local frame, and synthesizes F/I/D. No src import is used. Named thresholds are read from metrics.json and actually included in the pass decision.
