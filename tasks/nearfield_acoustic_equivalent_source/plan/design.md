# Shipped interfaces and flow

`python -m src.main` sets CPU torch threads to1, loads data/raw_data.npz, calls solve with method TGV and20000 iterations, and writes output/reconstruction.npz. It does not import the upstream repository or run a learned model. No library module changes the Matplotlib backend.

preprocessing.load_pressure(path) reads NPZ with allow_pickle=False, requires finite complex64(1,9,12) pressure and nonzero norm, and returns complex64(9,12) in U. physics_model.coordinates(shape,width_m=.825,height_m=.6,z_m=0) returns float64(N,3) inclusive row-major coordinates in m. propagator(distance_m=.025,frequency_hz=1150) returns complex64(108,2000); it rejects coincident source/receiver points. forward(q,distance_m=.025,frequency_hz=1150) returns complex pressure(9,12). adjoint(pressure,distance_m=.025) returns the Hermitian-transpose field(40,50), without an inverse claim.

solvers.difference(q,order=2) accepts torch tensor (...,H,W), returns (...,H,W,2), x then y, index-unit derivative. difference_adjoint(u,order=2) returns (...,H,W). data_gradient(q,p,G) uses tensors q(1,1,40,50), p(1,1,9,12), G(1,1,108,2000) and returns the same q shape. project_dual(u,weight) returns pixelwise projected complex vectors. solve(pressure,method='TGV',iterations=20000,snr_db=None,return_history=False) returns a complex64(40,50) NumPy image and diagnostics containing lambdaa,smax,tau, optionally sigma, and history dictionary. Allowed methods LN/TV/TGV; default SNR is30 for LN and35 otherwise. History retains requested fixed iteration checkpoints as q/u NumPy snapshots. There is no file side effect in solve.

visualization.review(task_dir,figure_dir) is the active notebook comparison path. It loads public pressure and the identified original method arrays, actively runs LN/TV/TGV plus actual regularization sensitivity, calls independent Judge on fresh TGV, builds five scientific figure groups, and exports each as PNG/SVG/PDF with numeric_sources.npz and metrics.json. It returns figures and the numeric summary. The figure directory comes from IMAGING_FIGURE_DIR when executing the notebook. These diagnostics are not required submission outputs.

evaluation/judge.py is standalone NumPy and uses its own independent complex128 propagation equation; it never imports src. Hidden references resolve relative to the Judge file; existing ground_truth.npz takes priority over baseline_reference.npz. Prediction and report CLI paths resolve relative to the caller. Input must be exactly complex64(1,40,50), required key reconstruction, finite. JSON reports status/pass flag/metrics/comparison boundaries/errors; exit0 pass,1 scientifically valid below thresholds,2 malformed or evaluator failure. Invalid reports have empty metrics. Reference comparisons apply no alignment. All tests/fixtures are under test; upstream numerical captures are documented in validation.md.
