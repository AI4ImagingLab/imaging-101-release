# Shipped implementation and execution flow

## Interfaces

`src.preprocessing.load_data(path=None)` reads the default task-relative data/raw_data.npz with allow_pickle=False, copies the sole batch into a dictionary of four 1-D arrays, and validates shape (401,), finite values, positive uncertainties and instrument int64 labels exactly {0,1,2}. time/velocity/uncertainty use float64, in BJD days/m/s/m/s; instrument uses dimensionless int64. It has no write side effect.

`src.physics_model.solve_kepler(mean_anomaly, eccentricity)` accepts float arrays in radians and a broadcastable eccentricity, returning float64 eccentric anomaly with identical shape. It performs the explicit native third-order update and raises on more than 100 updates. `transit_to_periastron(tc, period, eccentricity, omega)` maps scalar BJD days/days/unitless/radians to periastron BJD. `planet_velocity(time, period, tc, eccentricity, omega, amplitude)` accepts a 1-D time axis and scalar physical orbital entries, returning float64 velocities in m/s. `unpack_orbits(vector)` converts the internal (16,) vector to a (2,5) physical array ordered P,T,e,omega,K. `components(time, vector)` returns the (2,N) velocity contribution of each planet. `forward(time, instrument, vector)` returns (N,) total velocities, including unknown instrument offsets.

`src.solvers.log_prior(vector)` returns the scalar dimensionless normalised log prior or negative infinity outside support. `negative_logposterior(vector,data)` returns the scalar dimensionless negative log posterior or positive infinity, with variance in squared m/s. `reconstruct_native(data, initial=None, fixed=None)` returns the native finite Powell baseline and diagnostics, preserving the original last-evaluated-vector convention. It is called as a baseline and one computed starting point. `precision_fit(data,start,fixed=None)` optimises the same physical posterior in affine coordinates with tighter stopping tolerances and returns an explicit optimum (16,) vector plus success/message/iterations/evaluations/negative_logposterior. `reconstruct(data, initial=None, fixed=None, multi_start=None)` is the primary routine. With no explicit initial or fixed coordinates it runs four native/prior-based starts, selects the lowest posterior objective, and returns (vector, diagnostics). With an explicit initial vector it defaults to one precision fit, for local noise experiments; multi_start can override this choice. Diagnostics include the selected run's values, selected_start and a runs list with every optimisation's diagnostics. The real float64 vector ordering and units are specified in approach.md. All these routines evaluate the local likelihood and never load a reference, upstream package or checkpoint. `submission(vector)` returns the batch-first output dictionary: reconstruction (1,2,5), instrument_offset (1,3), instrument_jitter (1,3), all real float64.

`src.visualization` contains plotting and metric helpers called by the notebook. These functions accept actual calculated arrays; they never recover a result from a cache and do not select Matplotlib's backend. `residual_diagnostics(data,vector)` returns residual (N,) m/s, total sigma (N,) m/s and scalar dimensionless weighted RMS. `parameter_errors(vector,reference)` returns (16,) absolute physical errors with the documented periodic epoch/angle convention. `plot_observations(data)`, `plot_fit(data,vector,upstream,native=None)` and `plot_phases(data,vector)` each return a Matplotlib Figure. `phase_bins(phase,velocity)` returns centred-cycle coordinates, mean velocities and standard errors from the native 25-bin two-cycle summary; bins with fewer than three observations are omitted. Small negative variance from floating-point cancellation is clipped to zero solely in this display helper. All plot functions leave display to their caller. The notebook owns all figure creation and display. No library module calls matplotlib.use.

`src.main.main()` is the standard entry point for `python -m src.main`: read public observations, call reconstruct with all sixteen parameters free, convert to output arrays, create output/ and write output/reconstruction.npz, then print diagnostics. It does not import plotting helpers, run the Judge or read hidden assets.

## Independent evaluation and files

`evaluation/judge.py` contains independent physical-output metrics and a separate Newton Kepler implementation for observation consistency. It imports NumPy and the standard library only and never imports src. The CLI accepts --prediction and --report; those paths follow the caller's current working directory. The hidden baseline_reference.npz and metrics.json paths are resolved beside the evaluator; ground_truth.npz takes precedence if supplied by an evaluator, but no actual ground-truth file is shipped in this real-observation task. Public observations for observation consistency are resolved at data/raw_data.npz beside the task. All predicted/reference arrays must meet exact keys, shapes, float64 dtypes and finiteness. Invalid input or unavailable evaluator assets yields status error and empty metrics. Valid poor estimates yield fail. JSON reports include thresholds/comparison direction, errors, status and passed, and create their parent directory; exit codes are 0/1/2 for pass/fail/error, including report-write failure.

`test/fixtures` contains independently captured initial, final and stage arrays from the unchanged original source on all 401 observations. Tests consume these arrays without importing original code. The independently precision-refined original final vector is also represented as physical quantities in evaluation/baseline_reference.npz. `notebooks/reference_outputs/upstream_map.npz` has precision-refined original vector/model and native early-stop vector/model for the active notebook's comparisons; it is not a reconstruction input. `notebooks/reference_outputs/fresh_measurements.npz` contains a separately identified local vector and measured runtime; the notebook reads it only after the active reconstruction to report repeat agreement. Neither reference file supplies the active solution. These separate assets have distinct documented consumers. The notebook does not read a saved cleaned reconstruction to supply its fresh method. It separately recomputes the native early-stop baseline and compares it with its identified original arrays; the main scoring reference remains the improved original-API MAP.

## Notebook flow and effects

The notebook establishes the task root, imports cleaned modules and loads public observations. It fits the complete benchmark afresh, loads the original numerical result only for comparison, and computes physical-output and residual metrics. It then creates time-domain and phase-folded data/model panels, orbital/reflex-geometry views, parameter/instrument comparisons, residual/noise diagnostics, fitted ablations and noise-sensitivity plots. Noise experiments copy the observations before perturbation and rerun the full optimiser with the freshly fitted vector as a local starting point. Their results are explicitly local sensitivity measurements; they are not used as output references or claimed posterior samples.

No upstream imports, network access, original repository path, task-crossing import or opaque orbital model is required at runtime. Maintainer original source, primary paper PDFs, capture drivers, full logs and executed notebook remain outside the package. Shared runtime dependencies are NumPy, SciPy and Matplotlib, pinned as documented. CPU single-thread execution is the validated path; the task requires no accelerator.
