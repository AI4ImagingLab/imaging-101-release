# Evaluation Validation

The hidden truth is a simulated 64 x 64 Jy/pixel image under key `reconstruction` in `ground_truth.npz`. The visible input was repackaged from the local benchmark asset archive: its original `raw_data.npz` SHA-256 was `E79E5684148ACAC7945DD530926DC05BD6125DF18DFCF0DE9A3C09A5F0F21256`. The released batch-first file SHA-256 is `CE83ECBBFE6D76F39F1287828340C16572C05CBF346E2A632484BCD33CE797BC`. Calibrated visibilities and calibrated closure quantities were removed; truth was moved out of `data/`.

The archived standard-method results reproduce the original notebook metrics against simulated truth: calibrated Vis RML NCC 0.9669 / NRMSE 0.0340; calibrated closure-only NCC 0.7523 / NRMSE 0.1056; gain-corrupted closure-only NCC 0.6044 / NRMSE 0.1384. The first two use calibrated observations stored only in hidden maintainer reference outputs. The released solver only receives corrupted observations, so the Judge baseline is the gain-corrupted closure-only reconstruction: cosine NCC 0.6044211252 and dynamic-range NRMSE 0.1384213641 after applying the known 0.6 Jy flux scale. Boundaries use 0.9 times this NCC and 1.1 times this NRMSE. The cleaned `src/main.py` produced NCC 0.6443973091 and NRMSE 0.1173349048; `judge.py` passed both. No alignment or evaluation-time rescaling was applied.

These numbers establish format and pipeline compatibility, not a new scientific quality claim. The archive did not include an upstream commit identifier or a reproducible execution log for the exact bundled observations. The independent upstream `ehtim` run required by the full cleaning specification remains unverified in this format-only update. The six archived comparison reconstructions and the numeric parity fixtures remain under `notebooks/reference_outputs/` and `evaluation/fixtures/` for maintainers.

## Numerical migration audit

The original notebook at local `origin/main` cached a cleaned-code corrupted result with NCC 0.6285 and NRMSE 0.9385, and an ehtim reference with NCC 0.6044 and NRMSE 1.0778. Those cached NRMSE values use L2-error/reference-L2 normalization, whereas the checked-in visualization source and current Judge use RMS-error/reference-range normalization. For this truth array the conversion factor is 7.7867045686. The archived reference image gives 1.0778462681 under L2 normalization and 0.1384213641 under range normalization. This metric change cannot explain an NCC difference.

All public observation values equal the archived observation arrays after removing the new batch dimension. `solvers.py`, `physics_model.py`, and `visualization.py` are identical to local `origin/main`. However, the migration recomputed pixel pitch as `9.69627362219072e-12` instead of preserving the archived `9.696273622188272e-12` radians. Controlled runs changing only this constant in the same environment produced NCC 0.5843285978 / range NRMSE 0.1309348734 with the recomputed value, and NCC 0.6443973091 / range NRMSE 0.1173349048 with the original value. The latter has L2-ratio NRMSE 0.9136522395. The loader and README now preserve the original value verbatim; the metadata fixture test checks exact constant equality rather than an absolute decimal-place comparison that masked the discrepancy.

The remaining difference between the historical cached NCC 0.6285 and the present NCC 0.6444 is not established by the available archive. The old notebook records Python 3.11.15, while this run uses Windows Python 3.12.4, NumPy 1.26.4, and SciPy 1.13.1. The optimizer is a nonconvex, numerically sensitive L-BFGS-B run. No exact reproduction of the historical runtime or attribution of the remaining difference to a particular package is claimed.
