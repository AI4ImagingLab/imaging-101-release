## Ambiguities, failed checks and corrections

1. The source IIO PFM writer writes rows directly top-down, unlike the standard bottom-up independent measurement PFM. An initial generic parser reversed the source output and produced invalid quality reports. Inspection of iio.c plus a separately compiled known2x3 matrix with rows11,12,13 and21,22,23 establishes the format distinction independently of reconstruction agreement. Source PFM parser now explicitly uses top-down; measurement parser uses standard bottom-up. This is format interpretation, not a fitted output alignment. Initial failed metrics and known-case commands are archived.
2. Before local extraction, a NumPy2 scalar-promotion draft computed depth or a reference norm in float32. It was rejected and archived; final camera conversion/metrics use float64 with float32 output serialization. Final criteria were regenerated before local code existed. Source reconstruction did not change.
