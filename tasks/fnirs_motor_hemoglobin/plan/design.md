# Shipped interfaces and execution

All modules use local NumPy mathematics and have no MNE/HDF5 or other domain-library dependency. Array order is batch, pair, component, sample unless stated. Computation and output are float64.

- `preprocessing.load_observations(path)` loads NPZ with allow_pickle=False and returns copies in a dict: intensity (1,68,2,4860) instrument units, distances (1,68) m, extinction (1,2,2) m^-1 mM^-1 and positions (1,68,3) m. It rejects wrong recording shape, nonfinite values, nonpositive intensity/distances. It does not alter stored precision or coordinates.
- `preprocessing.optical_density(intensity)` accepts a finite positive real intensity array and returns same-shaped float64 natural-log optical density using the final axis arithmetic mean. No file side effect.
- `physics_model.absorption_matrix(extinction, distances, ppf=6.0)` accepts E (1,2,2), d (1,P), scalar or two-component factor and returns A (1,P,2,2) mapping mol/L to OD. Rejects nonpositive factors/distances.
- `physics_model.forward(concentration, extinction, distances, ppf=6.0)` accepts c (1,P,2,T), returns OD (1,P,2,T). `adjoint(optical_density, extinction, distances, ppf=6.0)` applies the Euclidean matrix transpose to a same-shaped dual array. Both are side-effect free.
- `solvers.invert_density(density, extinction, distances, ppf=6.0)` solves all two-by-two systems by explicit cofactors, returns same-shaped concentration in M, raises ValueError for singular calibration. `reconstruct(intensity, extinction, distances, ppf=6.0)` composes optical density and that inverse.
- `main.run(data_path='data/raw_data.npz', output_path='output/reconstruction.npz')` loads observations, computes the complete canonical reconstruction, creates output parent and writes only the reconstruction key. Returns `(concentration, runtime_seconds)`. Standard `python -m src.main` invokes run and prints timing JSON. Module import does not select a plotting backend.
- `visualization.metrics(estimate,reference)` returns per-species numerical metrics consistent with independently tested Judge definitions. `visualization.experiments(obs,reference)` actively reconstructs all experiment arrays and returns dict of arrays/measurements. `visualization.figures(obs,results)` returns three Matplotlib figures named recording, parity_identifiability and sensitivity_channel_maps, without saving or displaying. The notebook itself creates the fourth regularization_short_regression figure from the already computed experiment arrays. Image time extents place sample0 at0seconds and sample4859 at544.208seconds using half-sample outer boundaries. It never changes backend. Notebook/maintainer caller owns closing/displaying/saving.

Flow: public NPZ -> validation -> mean/log -> explicit spectral inverse -> output NPZ. Public positions are not used by inversion; they provide the channel map for review. Notebook reconstructs again through these same cleaned modules, loads the separately identified upstream result for parity, computes all perturbation comparisons, evaluates with standalone Judge, and explicitly displays figures exactly once. Optional comparisons do not feed canonical output.

`evaluation/judge.py --prediction ... --report ...` is an independent CLI using only NumPy and the standard library. Hidden paths resolve from its own directory. It prioritizes ground_truth.npz when present, otherwise baseline_reference.npz. It validates shape, real float64 and finiteness, scores both chromophores and forward consistency, writes strict UTF-8 JSON and returns 0/1/2 for pass/fail/error. Prediction/report paths are caller-relative. Report parent is created; report-write failure returns 2. It never imports solver code.

`test/fixtures/upstream_stages.npz` is consumed only by full-stage parity tests; it was frozen by original MNE before extraction. Evaluation baseline supplies Judge and notebook comparisons; `notebooks/reference_outputs/upstream_measurements.json` identifies independent original run and `fresh_measurements.json` identifies cleaned measurements. Unit and comparing tests use private temporary directories. No raw format reader, upstream source, paper PDF, capture script or domain library is shipped.
