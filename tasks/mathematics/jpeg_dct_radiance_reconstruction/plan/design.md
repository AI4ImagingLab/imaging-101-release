# Shipped interfaces and execution flow

`python -m src.main` calls `main()` in `src/main.py`. It resolves the task root relative to its own file, loads `data/raw_data.npz`, reconstructs all coded pixels, creates `output/` when needed and writes `output/reconstruction.npz`. `main()` returns the computed unbatched array as well. It neither reads hidden references nor changes the Matplotlib backend.

`src/preprocessing.py` exposes `load_observations(path)`. The path can be a string or `Path`. It opens NPZ with `allow_pickle=False`, validates native integer coefficient shape/dtype and positive uint16 quantization tables, then returns independent unbatched copies `(coeff,q)`, with shapes `(3,54,80,8,8)` and `(3,8,8)`. It performs no RGB conversion or target estimation.

`src/physics_model.py` contains `blocks(u)`, `image(b)`, `transform(u)`, `inverse(b)`, `tv_gradient(u)` and `objective(u,coeff,q)`. For generic multiple-of-eight height/width, the first four map between `(channel,height,width)` spatial images and `(channel,block_row,block_column,frequency_row,frequency_column)` blocks. `transform` and `inverse` use an orthonormal type-II DCT and its inverse, with one worker. `tv_gradient` expects three channels and returns the spatial joint-TV subgradient in the same shape. `objective` returns a Python float representing the complete public TV-plus-coefficient criterion. Neither operation clips input intensities or shifts channel means. Pixel units and centered encoded intensity conventions are fixed by README.

`src/solvers.py` exposes `reconstruct(coeff,q,iterations=2000)`. It returns a float32 `(3,432,640)` reconstruction for the bound data, and has no file or plotting side effects. Quantization tables are converted only for arithmetic; input integer arrays are not modified. It implements initialization, acceleration, normalized channel steps and coefficient-box projection locally. The algorithm and default update count are explained in approach.md. No domain solver, checkpoint, cross-task module or archived source is imported.

`src/visualization.py` provides `rgb_preview(u)` and `comparison_figure(midpoint,fresh,upstream,tv2)`. The former returns an RGB display array with the 427 physical rows, using standard centered YCbCr conversion followed by display clipping to `[0,1]`. This intentional display crop and clipping never enters reconstruction, the NPZ submission or scoring. The latter returns a Matplotlib Figure with four labeled measured/reconstructed/diagnostic panels. It does not call `show` or save files. Scientific scores are computed independently from the full coded arrays, not display RGB.

The maintainer notebook loads visible observations through `load_observations`, actively calls `reconstruct` for the complete selected 2000-update path and a short 50-update comparison, and scores its fresh result using the independent Judge. It loads `notebooks/reference_outputs/upstream.npz` for actual original TV50 and the defective TV2 diagnostic, and `evaluation/baseline_reference.npz` for original TV2000. It never substitutes these stored outputs for freshly labeled local results. `test/fixtures/upstream_states.npz` is consumed by stage and full-pipeline parity tests; all fixture values were captured by original-C execution before this task was packaged.

`evaluation/judge.py` is standalone and imports no solver modules. Its `score(u,coeff,q)` separately implements the orthonormal DCT, public objective and coefficient-interval violation. `evaluate(prediction)` returns a report and an exit code. `main()` implements the required `--prediction`/`--report` CLI. Evaluator calibration and metrics paths are resolved relative to its own location; CLI paths retain the caller's working directory. It validates NPZ keys, complete shape, real float32/float64 dtype and finiteness before scoring. It writes UTF-8 strict JSON, returns 0/1/2 for pass/below-quality/error, and reports write failures on stderr. There is no submitted-code import or hidden-reference image comparison.

`evaluation/baseline_reference.npz` preserves the original method's full centered-channel result, explicitly a method reference rather than actual truth. It is not the Judge's scoring identity. `evaluation/metrics.json` stores the fixed objective and feasibility boundaries. `output/reconstruction.npz` is the latest fresh CLI result and `output/judge_report.json` is its independently generated report. Tests and provenance stay under `test/`, with no parallel test tree.
