# Shipped interfaces and caller flow

The standard entry is `python -m src.main` from this task's workspace. `main.run(data_path='data/raw_data.npz',output_path='output/reconstruction.npz')` calls the local loader and reconstruct function, creates the output parent, writes both required arrays and returns unbatched `(restored,transmission)`. It never reads evaluation assets. Relative CLI paths refer to the caller's working directory. Importing main or any library module does not select a Matplotlib backend. The CLI does not produce scientific figure files.

`preprocessing.load_observations(path=Path('data/raw_data.npz'))` loads with allow_pickle=False, copies the first batch and returns `(image,airlight)`: float64(H,W,3) normalized intensity and float64(3,) normalized intensity. It checks RGB, finite ranges and nonzero airlight. The bound public shapes are(1,400,600,3) and(1,3).

`physics_model.image_formation(radiance,transmission,airlight)` maps (H,W,3),(H,W),(3,) to (H,W,3) normalized observation. `recover_radiance(image,transmission,airlight,gamma=GAMMA,leave_haze=1.06)` returns clipped gamma-corrected normalized RGB using the source display bias. GAMMA=1.0. `rgb_to_gray(image)` returns(H,W) float64 guidance with the explicitly validated Octave coefficients. No function changes the inputs in place or performs I/O.

`solvers.haze_line_estimate(image,airlight,points,gamma=1.0)` takes(H,W,3),(3,),(1000,3), and returns initial transmission(H,W) plus a dictionary: radius/radius_new/lower/radius_std/weight(H,W), labels(H,W) integer0-based indices, count(1000,),directions(H,W,3). The data are dimensionless; count is a number of pixels. `SPHERE_POINTS` is an explicit local float64 constant taken from the original method's fixed discretization. No file is downloaded/read to construct it at runtime.

`weighted_system(initial,weight,guidance,lam=.1)` accepts(H,W),(H,W),(H,W,3) float arrays and returns `(matrix,rhs,modified,reliability,smooth)`: CSR(N,N),float64(N,),float64(H,W),float64(H,W),CSR(N,N), where N=H*W. Column-major flattening matches the sparse diagonals and top-row boundary anchor. The two CSR matrices encode the explicit local graph; they are not an upstream inverse operator. `refine_transmission(initial,weight,guidance,lam=.1)` solves the system, returns transmission(H,W) and a dictionary with those five objects named matrix,rhs,anchored,reliability,smooth. No file writes occur.

`contrast_stretch(image,percentiles=(.005,.995))` returns restored uint8(H,W,3) counts and float64(2,3) limits. It explicitly evaluates source order statistics and channel-wise remapping, rather than using an opaque imaging reconstruction API. Constant RGB arrays raise a descriptive error; this unsupported case does not occur in the benchmark.

`reconstruct(image,airlight,points=None,gamma=1.0,lam=.1)` uses SPHERE_POINTS when points isNone. It returns `(restored,transmission,stages)` with uint8(H,W,3),float64(H,W),and merged stage dictionary. Additional keys are initial,transmission,radiance(H,W,3),contrast_limits(2,3), plus the graph-system keys. It does not cache outputs or read hidden assets. Any caller requesting a different lambda performs a fresh solve.

`visualization.compare(estimate,reference)` returns numeric ncc/nrmse using the same mathematical metric definitions as the independent Judge. The nondegenerate benchmark comparisons are its intended input; independent known-vector tests check normalization. `style()` changes plot styling only when explicitly called. `image_panel` is a general plotting helper. Six story-figure functions are `observations_and_recovery(image,restored,t)`, `haze_line_mechanism(image,airlight,stages)`, `source_comparison(restored,t,original_image,original_t)`, `refinement_ablation(image,stages)`, `sensitivity(stages,image,settings=(.03,.1,.3))`, and `physical_and_display_conventions(image,airlight,t,restored,stages)`. First four return a Figure; sensitivity additionally returns fresh field arrays and metric records; last additionally returns physical-inverse/residual arrays. No figure uses an archived reconstruction as a fresh result.

`export_figures(figures,directory,numeric_sources,metrics)` is an optional maintainer export helper. It creates the **explicitly supplied private directory**, exports each named actual Figure asPNG/SVG/PDF, records their SHA256 manifest, writes numeric_sources.npz and metrics.json. The canonical Notebook uses this helper only if IMAGING101_FIGURE_DIR is set. It always computes and displays every scientific comparison, irrespective of export mode.

The active Notebook uses six chapters. It loads raw observations, records actual Python/package/backend versions, actively reconstructs, writes/evaluates a new submission, loads frozen upstream comparisons from notebooks/reference_outputs, and computes all ablations/sensitivity/physics comparisons locally. Reference_outputs/upstream_outputs.npz supplies independently run normalized-input RGB/transmission; original_uint8_input_comparison.npz supplies the separately labeled original uint8-input preprocessing-equivalence check. The evaluator independently consumes evaluation/baseline_reference.npz. test/fixtures/upstream_stages.npz supplies independently frozen original intermediate stages solely to comparison tests. These intentional consumers and archive hashes are recorded in validation.md. No cross-task imports or upstream checkout are used by task source, tests, Judge or Notebook.

`evaluation/judge.py --prediction ... --report ...` is a separate process with its own strict shapes/dtypes and metric calculations. Hidden assets are resolved relative to the evaluator file; prediction/report paths follow caller cwd. It never imports src. It validates config/reference/prediction before scoring, writes status/pass/metrics/thresholds/errors JSON, and returns0pass/1valid poor/2malformed or evaluator/report-write error. If actual ground_truth.npz ever exists it takes precedence; no such truth is fabricated for this real photograph.
